# 合并流水线实验归档

本目录保存完整的流水线与串行 A/B 工程快照，不参与 MyServer 主工程编译。主工程当前采用串行合并，合并性能计时和模式切换均已移除。

## 内容

- `source/`：归档时的完整工程，包括 ReliableMergeHasher、模式切换、合并计时、资源和原有用户注释。
- `tests/`：实验验证源码、qmake 配置与驱动；配置已改为引用本目录 source，避免误用当前串行源码。
- `evidence/`：验证结果、实验日志、源文件清单和清理前的学习笔记副本。
- 原 A/B 改动记录及两个启动脚本：实验过程快照；运行脚本前需要重新编译并部署 MyServer.exe 到脚本旁。

## 结果与决定

同一 MyServer 工程、同一文件 ext4.vhdx（7,132,413,952 字节），同机自发自收且同一物理磁盘，最新一组为：

| 阶段 | 流水线 | 串行 |
| --- | ---: | ---: |
| 总计 | 14,003.6 ms | 9,138.4 ms |
| 读取 | 5,511.9 ms | 2,948.7 ms |
| 写入 | 6,902.9 ms | 1,822.6 ms |
| SHA-256 | 3,879.7 ms（重叠） | 3,554.2 ms |
| commit | 1,411.0 ms | 668.0 ms |

流水线增加 4,865.2 ms，约 53.2%。等空闲缓冲与摘要收尾仅 35.6 ms，摘要基本跟得上；新增时间主要在读写与提交。先测流水线、后测串行，缓存和后台负载可能影响结果；并发引起的内存访问、调度和写入节奏变化也只是待验证解释，尚未定位根因。Windows 缓存读写与回写机制可参见 [Microsoft 文件缓存说明](https://learn.microsoft.com/en-us/windows/win32/fileio/file-caching)。

因此主工程保留平台加速 SHA-256 和串行合并，实验实现独立归档。此结论针对当前观测，不推广为所有硬件都不适合流水线。

## 重建实验程序

配置匹配的 Qt / MinGW 环境后，在本目录独立创建 build，进入它执行：

```powershell
qmake '../source/MyServer.pro' 'CONFIG+=release' 'CONFIG-=debug'
mingw32-make -j4
```

归档程序默认流水线；给新接收进程设置 MYSERVER_MERGE_MODE=serial 使用串行。需要便携运行时，对编译生成的 EXE 重新执行 windeployqt。旧的二进制、测试数据和部署目录没有保存在本目录。
